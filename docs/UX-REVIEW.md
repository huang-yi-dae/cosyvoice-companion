# UX / UI 流程审查报告

> 审查视角：UI 设计师
> 审查对象：CosyVoice Companion Web 前端（工作室 / 管理台 / 自动化 / 模型 / 陪伴 5 页）
> 结合项目定位：**个人研究用途**的本地工具（Windows / 单用户 / 隐私敏感）
> 说明：本报告只针对 **交互与界面流程**，不涉及后端算法。已完成的 P1–P4 优化不再重复列出。

---

## 0. 总体评价

当前前端在**视觉一致性**（Glass Studio 设计系统统一、5 页共用 CSS）和**核心链路可用性**上
已经达到较高水准。P1–P4 修掉了最扎眼的几个交互坑。

但从设计师视角看，**真正影响体验的短板不在"单个控件好不好看"，而在"流程与心智模型"层面**——
即用户能否在第一次使用时理解"我该先做什么、现在到哪了、为什么卡住"。下面按严重程度分级。

评级说明：🔴 阻断/高频困惑 · 🟡 明显摩擦 · 🟢 打磨项

---

## 1. 🔴 核心流程问题（最该优先解决）

### 1.1 缺少「首次使用」的引导与流程编排
**现象**：5 个页面是平级并列的（工作室 / 管理台 / 自动化 / 模型 / 陪伴），
但它们之间其实有**强先后依赖**：
```
自动化(跑流水线) → 管理台(确认数据/人设) → 工作室(合成) / 陪伴(对话)
     └── 前提：模型页要先下载好模型
```
**问题**：新用户打开默认落在「工作室」，但此时很可能**还没有任何用户数据、也没下载模型**，
于是看到的是"该用户暂无语音样本""模型加载失败"——**在错误的起点遭遇空状态**，不知道该去哪。

**设计建议**：
- 首次进入时，若检测到「无用户 / 无模型」，工作室应显示**引导卡片**而非干瘪的"暂无"，
  明确指引："① 先到 [模型] 下载 CosyVoice-300M → ② 到 [自动化] 跑一遍流水线 → ③ 回到这里合成"。
- 或者把「自动化」设为**新用户的默认落地页**，并在其顶部放一个「4 步走」进度总览。
- 顶栏导航可按流程顺序重排：**自动化 → 管理台 → 模型 → 工作室 → 陪伴**（当前顺序偏随意）。

### 1.2 空状态（Empty State）只有一句话，缺少「下一步」出口
**现象**（代码可查）：
- 工作室无样本："该用户暂无语音样本。"
- 管理台未选用户："请选择一个用户。"
- 收藏夹为空："尚无保存的语音。"
- 无用户："未发现用户"

**问题**：这些空状态是**死胡同**——告诉用户"没有"，却不告诉"怎么才能有"。
对个人工具尤其致命，因为没有客服、没有新手教程，用户只能靠猜。

**设计建议**：每个空状态都应带**一个明确的行动按钮或指引**，例如：
- 无样本 → "该用户还没有语音样本，[去自动化页跑转码] 或 [切换其它用户]"。
- 无用户 → "还没有可分析的用户，请先到 [自动化] 完成一次流水线"。
- 收藏夹为空 → "合成的语音可点『保存到收藏』留在这里"。

### 1.3 「当前用户」是全局关键状态，却缺少足够的存在感
**现象**：当前 QQ 用户只在**右上角一个小胶囊**里显示，且要点开才看到列表。
P2 已解决"跨页面记住"，但**可见性**仍不足。

**问题**：合成 / 对话 / 数据都强绑定"当前是谁"，一旦用户记错了当前对象，
就会"用 A 的样本合成、却以为在做 B"。个人工具里多对象切换很常见，风险高。

**设计建议**：
- 在每个页面的 `page-head`（大标题区）里**回显当前用户**，例如标题旁加一枚
  "当前：QQ 123457824"的 chip，让"我在给谁做"始终在视线内。
- 用户切换后，除 toast 外可考虑**短暂高亮 page-head**，强化"上下文已切换"的感知。

## 2. 🟡 明显摩擦点

### 2.1 危险/不可逆操作缺少二次确认
**现象**：
- 管理台知识库路径的删除（✕）是**即时生效、无确认、无撤销**。
- 管理台 System Prompt「重新生成」会**直接覆盖**文本框内容——若用户手动改过还没保存，一键即丢。

**设计建议**：
- 删除路径 → 至少加一个"撤销"toast（点了可恢复），或轻量二次确认。
- 「重新生成」若检测到当前文本有未保存改动 → 先弹确认"这会覆盖当前内容，继续？"。

### 2.2 System Prompt 有"未保存改动"却无任何提醒
**现象**：管理台的 Prompt 是一个大 textarea，改完需手动点「保存」。
但**切换用户 / 离开页面时不会提示"你有未保存的修改"**。

**设计建议**：
- 监听 textarea 变化，标记 dirty；在切换用户或关闭前，若 dirty 则提醒。
- 「保存」按钮可根据 dirty 状态高亮（有改动才亮），给用户明确反馈。

### 2.3 长耗时任务完成后，反馈"一闪而过"
**现象**：
- 模型下载完成 / 流水线跑完，只弹一个 **2.6 秒后消失的 toast**。
- 用户很可能切走去做别的，回来时 toast 早没了，只能靠自己判断"到底成没成"。

**设计建议**：
- 任务完成后，在对应面板留一个**持久的成功/失败卡片**（含耗时、结果摘要、下一步入口），
  而不是仅靠短暂 toast。流水线页已有"处理结果"面板，模型页建议对齐同样的持久反馈。

### 2.4 合成 / 对话缺少快捷键，操作节奏割裂
**现象**：陪伴页支持 `Enter` 发送（体验好），但**工作室的「开始克隆」、管理台的「保存」都只能点按钮**。

**设计建议**：
- 工作室文本框支持 `Ctrl/Cmd + Enter` 触发合成。
- 管理台 Prompt 支持 `Ctrl/Cmd + S` 保存（阻止浏览器默认保存对话框）。

### 2.5 文本输入无字数 / 长度反馈
**现象**：工作室「目标文本」、陪伴输入框都没有字数提示。
超长文本会显著拖慢合成、甚至劣化音质（ROADMAP #13 提到长文本分段尚未做）。

**设计建议**：
- 文本框下方显示实时字数；接近/超过建议阈值时给出温和提示（如"较长文本合成会变慢"）。

### 2.6 错误提示停留在"发生了什么"，缺少"我该怎么办"
**现象**：合成失败直接把后端 `detail` 抛出来（如 `请选择一个云端音色`、原始异常字符串）。
云端未配置 Key 时的提示相对好（有指引），但**本地合成的失败大多是"裸报错"**。

**设计建议**：
- 对常见失败做**归类 + 可操作建议**：如"模型未下载 → 去模型页下载"、
  "样本无效 → 换其它样本"、"首次加载超时 → 稍候重试"。

## 3. 🟢 打磨项（锦上添花）

### 3.1 移动端 / 窄屏适配未验证
- `grid.cols-2` 在窄屏会退化为单列（有断点），但 **voice-grid 卡片、聊天窗口高度**
  （`calc(100vh - 260px)`）在小屏可能拥挤。个人工具虽以桌面为主，但偶尔手机查看时体验会崩。
- 建议：至少保证 ≤768px 时顶栏导航不溢出、卡片不过窄。

### 3.2 加载态用文字"加载中…"，缺少骨架屏
- 列表加载时是"正在加载语音样本…"纯文字。可用 **skeleton 占位**，让等待更平滑、
  也避免布局在数据到达时突然跳动（CLS）。

### 3.3 试听与「合成结果」两处音频体验不统一
- 试听（P1）用的是极简的 ▶/⏸ + 波形；合成结果用的是**原生 `<audio controls>`**。
  两者视觉与操作方式割裂。可考虑统一为一套自绘播放器，或至少统一容器样式。

### 3.4 波形是"随机生成"的装饰，非真实波形
- Voice Card 的波形条是 `Math.random()` 生成的纯装饰。虽好看，但**传递了"这是真实波形"的错误暗示**。
  设计上要么弱化为纯律动动画（不像数据），要么（进阶）用真实音频峰值。

### 3.5 品牌 / 页面标题层级可更克制
- 每页 `page-head` 都是超大标题 + 副标题，信息量大时略"喧宾夺主"。
  工具型产品可让标题更收敛，把空间让给内容与操作。

## 4. 建议的优先级排期

| 阶段 | 项目 | 理由 |
|------|------|------|
| **P0（先做）** | 1.1 首次引导 / 流程编排、1.2 空状态出口、1.3 当前用户存在感 | 直接决定"新用户能不能上手" |
| **P1** | 2.1 危险操作确认、2.2 未保存提醒、2.3 完成态持久反馈 | 防止数据误丢 + 减少"成没成"的不确定 |
| **P2** | 2.4 快捷键、2.5 字数反馈、2.6 错误可操作化 | 高频操作的顺手度 |
| **P3** | 3.1 移动端、3.2 骨架屏、3.3 播放器统一、3.4 波形、3.5 标题 | 打磨与一致性 |

---

## 5. 一句话结论

> **当前 UI 的"颜值"已经到位，下一步的重点应从"组件级美化"转向"流程级引导"。**
> 对一个本地、单人、多对象、含长耗时任务的工具而言，
> 「让用户始终知道：我在给谁做、现在到哪一步了、卡住时该去哪」——
> 比任何视觉细节都更能提升实际体验。建议优先补齐第 1 节的三项核心流程问题。
